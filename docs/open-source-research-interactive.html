第一輪原始碼研究結論

不要選一個框架當「總腦」，而是吸收 6 套成熟設計的強項

我們自己的核心應維持 Adapter → Orchestrator → Event Bus → Durable State → UI。Claude / Codex / 其他 AI 只是 runtime provider，不應滲透到 UI 與排程策略。

最大發現：BAT 已經用實戰經驗證明「Renderer API 必須穩定、runtime 在下層適配、每個 session 只能有一個明確 runtime owner」；OpenAI Agents SDK 與 LangGraph 則證明「可暫停/恢復」一定需要明確 state machine + durable snapshot，而不是靠 prompt 記憶。

Architecture v1 的 5 個核心資產

① Unified Agent Adapter
② Deterministic Orchestrator
③ Unified Event Contract
④ Durable Run Snapshot
⑤ Human / Safety / Budget Gate

UI、模型、MCP、Worktree 都是可替換模組。

Orchestrator：採用「明確下一步」而不是自由聊天

OpenAI Agents SDK 把每一個模型 step 的結果限制在 RunAgain / Handoff / Final / Interruption；我們把它擴為：

type NextAction =
  | { type: "CONTINUE"; agentId: string }
  | { type: "HANDOFF"; to: string; contextRef: string }
  | { type: "RUN_TOOL"; toolId: string }
  | { type: "WAIT_INPUT"; requestId: string }
  | { type: "WAIT_APPROVAL"; approvalId: string }
  | { type: "FINAL"; resultRef: string }
  | { type: "FAIL"; error: NormalizedError };

排程拆分

Router：選 Agent
Workflow Engine：決定 NextAction
Context Manager：只傳必要上下文
Review Manager：控制 review round
Retry Manager：依 error class 決定 retry/handoff
Budget Manager：token/time/turn/stall
Human Gate：不可自動決策的點

Unified Event Contract

Hermes 的 telemetry 很實用，但我們不能依賴 Agent「自覺上報」。Adapter 能從 runtime 原生事件取得的，一律由 Adapter 自動產生；只有 runtime 不提供的語義才讓 Agent 補充。
interface UnifiedEvent {
  id: string;
  projectId: string;
  taskId: string;
  runId: string;
  agentId?: string;
  sessionId?: string;

  type:
    | "run.started" | "run.completed" | "run.failed"
    | "agent.started" | "agent.status"
    | "model.turn.started" | "model.turn.completed"
    | "tool.started" | "tool.completed" | "tool.failed"
    | "handoff.requested" | "handoff.completed"
    | "approval.required" | "approval.resolved"
    | "safety.blocked" | "budget.exceeded"
    | "runtime.warning" | "runtime.error";

  severity: "info" | "warning" | "error" | "critical";
  confidence: "confirmed" | "inferred";
  timestamp: number;
  data: Record<string, unknown>;
}

Checkpoint / Resume：借 LangGraph + RunState

LangGraph 把 thread_id 當 durable cursor；OpenAI Agents SDK 把 RunState JSON 當 pause/resume compatibility boundary。我們兩個概念都要。

RunSnapshot {
  schemaVersion,
  runId,
  taskId,
  currentStep,
  currentAgent,
  agentSessions,
  pendingApprovals,
  pendingInputs,
  budget,
  workflowState,
  lastEventId
}

非常重要的 resume 規則

Resume 不是重新 prompt 一次。已經完成的 tool side effect 不可以再執行；approval 要恢復到原 tool/call identity；schema 要版本化；不認識的新 schema 應 fail closed，而不是猜著恢復。

Safety / Approval Pipeline

Input Guard→ Agent Turn→ Tool Input Guard→ Approval?→ Side Effect→ Tool Output Guard→ Final Output Guard
採用 OpenAI Agents SDK 的 ordering 思想：guardrail 是 run state 的一部分；resume 後不能亂重跑 initial guardrail；tool input guard 在副作用之前，tool output guard 在結果被下一輪模型接受之前。

Architecture v1：8 條不可違反規則

#規則來源/原因
1Agent 不直接控制另一個 Agent。避免 Hermes-style direct signal 變成不可控 peer mesh。
2所有 handoff 必須由 Orchestrator 記錄並批准。可觀測、可限流、可恢復。
3UI 只能依賴 Unified API，不依賴 Claude/Codex event shape。BAT 的 compatibility contract。
4一個 session 只有一個 runtime owner。BAT 的 runtime ownership 原則。
5每個可中斷 run 都必須可 durable snapshot。LangGraph / Agents SDK / MAF。
6Auto Review 預設關閉，maxReviewRounds 預設 1。避免 Claude↔Codex usage loop。
7所有任務必須有 maxTurns / maxStall / time / token budget。Agents SDK + Codex Goal + MAF。
8Event Log append-only；Current State 是事件投影。方便 debug、replay、事故分析。

建議實作順序

1. Shared Types→ 2. Event Bus→ 3. Run State Machine→ 4. SQLite Snapshot/EventLog→ 5. Codex Adapter→ 6. Claude Adapter→ 7. Orchestrator Rules→ 8. Safety/Human Gate→ 9. WebSocket UI
MVP 成功標準不是「會聊天」，而是：啟動 Claude/Codex 任務 → UI 即時看到狀態 → 遇到 approval/block 可暫停 → 程式重啟後能從 snapshot 恢復 → 不重做已完成 side effect。
